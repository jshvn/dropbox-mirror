# dropbox-mirror simplification plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** Remove the round-trip, rclone and the reconcile-day observer; fetch from Dropbox over its API; store in R2 over S3 with boto3 under the AWS names jshvn/terraform uses; confirm a batch from the CLI's upload summary; make the weekly Proton walk budget-bounded and resumable and the independent verification. Delete everything the old design needed and the new one does not.

**Spec:** `docs/superpowers/specs/2026-09-03-dropbox-mirror-design.md` (revised 2026-09-04; binding). Measured facts behind it: the CLI upload summary on stdout is one JSON line `{"transferredItems":N,"transferredBytes":B,"skippedItems":S,"failedItems":F,"failures":[...]}` where folders count as transferred (a merged existing folder too) and content-identical files count as skipped; a Proton file node from `filesystem list -j` carries `type`, `uid`, `name.value`, `activeRevision.claimedSize`, `activeRevision.claimedDigests.sha1`; a Dropbox batch of 1,000 files uploads in about 650 s.

## Global Constraints

- Python >=3.13; runtime dependencies are exactly `requests>=2.32,<3` and `boto3>=1.35,<2`; tests use pytest; lint and format with ruff; every check runs inside the toolbox (`task test`, `task lint`).
- No AI attribution. No emojis outside markdown. Commits `<type>(<scope>): <summary>` under 75 chars, imperative.
- Comments and docs describe the current system only; no "replaces", "removed", "used to", donor or task references in code. Deleted code leaves no comment behind.
- Logs and the step summary carry counts, never mirrored path names. Secrets reach processes by environment variable name only.
- Plan-by-default: `batches`, `trash`, `reconcile`, `report`, `empty-trash` mutate only with `--apply`.
- A command exit status is never evidence. The upload summary's counts are the per-batch evidence; the reconcile walk's listing is the independent observation.
- Delete, do not stub: a module, table, config key, environment name, fixture, test, Taskfile line, Dockerfile line or README sentence that the new design does not use is removed in the task that makes it unused. `grep -ri 'rclone\|roundtrip\|round-trip\|round_trip\|observer' src tests config docker Taskfile.yml op.env .github README.md` is empty when Task 5 lands.
- Functions under 50 lines where the code is new; files under 800 lines.

**Steps:**

Methods: `get(key, target)` downloads with `download_file`, returns False on a `ClientError` whose code is `NoSuchKey` or `404`, raises `StoreError` on any other error; `put(source, key)` uploads with `upload_file`; `copy(source_key, target_key)` uses `copy_object` with `CopySource={"Bucket": bucket, "Key": source_key}` (server-side); `list(prefix)` paginates `list_objects_v2` and returns keys; `probe()` calls `list_objects_v2(MaxKeys=1)` and raises `StoreError` on any `ClientError`. 3. `tests/test_store.py`: a hand-written fake client class with `download_file`, `upload_file`, `copy_object`, `get_paginator`, `list_objects_v2` that records calls and raises `botocore.exceptions.ClientError({"Error": {"Code": "NoSuchKey"}}, "GetObject")` on demand; tests for every method, the missing-object False, the probe failure, and the unset-secret error. No network.

5. `Dockerfile`, lock file, `pyproject.toml`: as listed. Rebuild the image (`task image-clean && task image`) and verify `task run -- python -c "import boto3, requests; print(boto3.__version__)"` and `task run -- sh -c '! command -v rclone'`.

### Task 3: Confirm from the upload summary; the round-trip deleted; report and paths follow

**Files:**
- Modify: `src/migrator/phases/batch.py` (`confirm(ctx, batch_id)`, `checkpoint`, delete `roundtrip`, `_mismatch`, `_select`, `_downloaded_regular_file`, `ROUNDTRIP_*`, `now`, and anything else only the round-trip used; keep `resolve_children` and `parent_cli_path` for the trash phase), `src/migrator/phases/p40_batches.py` (steps fetch, verify, upload, confirm, checkpoint; totals), `src/migrator/phases/p70_report.py` (figures and sections per the spec), `src/migrator/paths.py` (delete `roundtrip`), `src/migrator/commands.py` (`clock` clears staging, report and chain), `src/migrator/state.py` (the `batch_items` status comment and the `cli_path`/`proton_uid` columns stay: trash and reconcile fill `proton_uid`), `tests/test_batch.py`, `tests/test_batches_loop.py`, `tests/test_report.py`, `tests/test_commands.py`, `tests/test_paths.py`, `tests/conftest.py` (`FakeProton` loses `download_file` and `downloads`; `upload_tree` returns a summary line built from its arguments).
- Do not touch: `p60_reconcile.py`, `proton_cli.py` (Task 4); `fetch` (Task 2).

**Steps:**
1. `upload` keeps writing the raw stdout to the phase artifact and returns `{"uploaded_files", "uploaded_bytes"}`.
2. `confirm(ctx, batch_id)`: read the artifact, take the last line that parses as JSON with a `transferredItems` key (raise `PhaseError("upload summary missing")` otherwise); count `files = VERIFIED rows` and `folders = directories under staging`; the batch is confirmed when `failedItems == 0`, `failures == []`, and `transferredItems + skippedItems == files + folders`; then every VERIFIED row becomes CONFIRMED and the counts `{"confirmed": files, "skipped_identical": skippedItems, "confirm_failed": 0}` are returned. Otherwise every VERIFIED row becomes CONFIRM_FAILED with a details reason naming the counts (never a path), the batch is marked FAILED by checkpoint, and `confirm` returns `{"confirmed": 0, "confirm_failed": files}`; the `failures` array is written to the artifact only (it may carry names).
3. `checkpoint` merges CONFIRMED rows (`proton_uid` NULL) and marks them CHECKPOINTED; FAILED when any CONFIRM_FAILED row exists; the push and the staging clear stay.
4. `p70`: "This run" rows are batches planned and completed, files fetched, vanished, hash-mismatched, uploaded, skipped identical, confirmed, checkpointed, trashed; throughput is Dropbox down and Proton up plus batch durations; verification is files confirmed this run and cumulative (`mirror_objects` rows), plus from the latest `reconcile figures` event (see Task 4's contract; absent means "no walk yet") the matched, dropped and strays figures and a mismatch line that must read zero; the "70 report" phase table row filter stays. Errors table: content-hash mismatch, upload failure, confirm failure, listing refused, session trouble, command non-zero exit.
5. Tests as listed; one test proves a summary with `failedItems: 1` confirms nothing and fails the batch, one proves the count identity with a merged folder counted as transferred.
6. `task test`, `task lint` green; `grep -ri 'roundtrip\|round-trip\|round_trip' src tests` empty. Commit.

### Task 4: The reconcile walk as the verification: SHA-1, budget, resume

**Files:**
- Modify: `src/migrator/providers/proton_cli.py` (`inventory(..., deadline=None)`), `src/migrator/phases/p60_reconcile.py`, `tests/test_reconcile.py`, `tests/test_proton_inventory.py`.
- Do not touch: `batch.py`, `p70` (Task 3 reads the figures event by contract).

**Steps:**
1. `inventory`: between folders, when `deadline` is set and `time.time() >= deadline`, stop and return the snapshot id with the snapshot left RUNNING (the next call with the same purpose and `reuse_complete=False` resumes its PENDING folders, as today). `test_proton_inventory.py` proves a walk stops at the deadline and resumes.
2. `p60`: deadline = `runs.start_epoch + runs.budget_minutes*60 - 600`; after the walk, when the snapshot is still RUNNING: push the state with label `<epoch>-reconcile`, log the figures event with `complete=0` and `folders_pending`, return PASS with `{"partial": folders_pending}`; nothing is dropped or trashed on a partial walk. When COMPLETE: compare every `mirror_objects` row with its Proton node by comparison key on size and on `claimedDigests.sha1` against `mirror_objects.sha1`; drop rows Proton lacks, mis-sizes or whose SHA-1 differs (each counted); record `proton_uid` for the rest (`uid_refreshed`); trash strays as today; log the figures event with `complete=1`; push; outputs as today plus `matched` and `sha1_mismatch`.
3. Retention stays one walk; a RUNNING snapshot being resumed is never pruned.
4. `task test`, `task lint` green. Commit.
